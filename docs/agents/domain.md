# Domain Docs

## Layout

Single-context: общая предметная область игры, `GLOSSARY.md` в корне репозитория,
архитектурные решения — в `docs/adr/`.

## Before exploring, read these

- Перед изучением кода прочитай `GLOSSARY.md`, если он существует.
- Прочитай решения из `docs/adr/`, относящиеся к текущей задаче.
- Если в будущем появится `GLOSSARY-MAP.md`, используй его как указатель на нужные словари и решения отдельных областей.
- Если файлов нет, продолжай без предупреждений и без предложения создать их заранее.
  Навык `domain-modeling` создаёт их по мере появления согласованных терминов и решений.
- Игровые решения и принятый стиль также сверяй с `.studioigor/DECISIONS.md`,
  `.studioigor/DESIGN.md` и `.studioigor/ART_BIBLE.md`, когда они относятся к задаче.

## Use the glossary's vocabulary

Используй согласованные названия понятий в задачах, предложениях и тестах.
Не заменяй их синонимами, которые словарь исключает. Если термина нет, проверь,
нужен ли он проекту, и передай существенный пробел в `domain-modeling`.

## Flag ADR conflicts

При противоречии существующему решению назови конкретный ADR и объясни,
почему его стоит пересмотреть. Не переопределяй принятое решение молча.
